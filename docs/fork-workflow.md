# Fork 同步与改造工作流

## 仓库结构

```
┌─────────────────────────────────────────────────────────┐
│                     Remote 远程仓库                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  upstream (只读)              origin (读写)              │
│  anomalyco/opencode    ←→    SuJingnan/opencode        │
│                                                         │
└─────────────────────────────────────────────────────────┘
                          │
                     git fetch / push
                          │
┌─────────────────────────────────────────────────────────┐
│                     本地仓库                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  dev 分支          ── 与上游保持同步，不在此开发          │
│  my-feature 分支   ── 所有改造在此进行                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 数据流向

```
upstream/dev ──fetch──→ 本地 dev ──push──→ origin/dev
                            │
                     merge / rebase / cherry-pick
                            │
                            ▼
                       my-feature ──push──→ origin/my-feature
```

## Claude Code Slash Commands

| 命令 | 功能 | 使用场景 |
|------|------|----------|
| `/sync-feature` | 一站式同步(推荐) | 日常使用，自动完成全部流程 |
| `/sync-check` | 仅查看上游新 commit | 只想看一眼，不做操作 |
| `/sync-dev` | 仅同步 dev 分支 | 只同步 dev，不处理 feature |
| `/push-feature` | 推送 my-feature 到 GitHub | 改造完成后推送 |

## 日常使用

```bash
# 在 Claude Code 中输入
/sync-feature
```

执行后会自动：
1. 拉取上游最新
2. 同步 dev
3. 列出新 commit 让你选择
4. 按你的指示合入 my-feature

## 原则

- `dev` 分支始终与上游一致，**不直接在 dev 上开发**
- 所有改造在 `my-feature`（或其他 feature 分支）上进行
- `upstream` 只读，永远不 push 到 upstream
- 遇到冲突时由人工决定如何处理
